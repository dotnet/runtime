# WebAssembly `producers` and `build_id` custom sections

.NET emits the WebAssembly tool-conventions
[`producers`](https://github.com/WebAssembly/tool-conventions/blob/main/ProducersSection.md) and
[`build_id`](https://github.com/WebAssembly/tool-conventions/blob/main/BuildId.md) custom sections.
The sections are non-semantic and may be stripped by tooling.

Related issues:

- [dotnet/runtime#91049](https://github.com/dotnet/runtime/issues/91049) - emit `build_id`
- [dotnet/runtime#96334](https://github.com/dotnet/runtime/issues/96334) - emit `producers`

## Ownership

Each component identifies the Wasm file it creates. There is no build-wide ID shared by all files.

| Artifact | `producers` | `build_id` |
|---|---|---|
| Mono/CoreCLR `dotnet.native.wasm` | Runtime-pack `dotnet-producers.s`, merged with compiler entries by `wasm-ld` | Generated by `wasm-ld` |
| Regular Webcil | `WebcilWasmWrapper`: `processed-by=WebCIL`, `sdk=.NET` | SHA-256 of the Webcil payload |
| R2R Webcil | `WasmObjectWriter`: `processed-by=WebCIL`, `sdk=.NET` | SHA-256 of the generated module before metadata is appended |
| NativeAOT relocatable Wasm object | `WasmObjectWriter`: `processed-by=ILCompiler`, `sdk=.NET` | None; the final linker owns the executable ID |

Webcil deliberately omits `language`: a managed assembly may originate from C#, F#, Visual Basic,
generated IL, or multiple languages. Native compiler inputs continue to contribute their own
language metadata.

## Native runtime links

Each .NET 12+ Browser runtime pack contains a flavor-specific
`runtimes/browser-wasm/native/dotnet-producers.s`. It contributes:

- `processed-by=<Mono|CoreCLR>` with the runtime-pack version
- `sdk=.NET` with the runtime-pack version

Application native relinks pass this assembly source to Emscripten. `wasm-ld` merges its section
with producer entries from other inputs, and `-sEMIT_PRODUCERS_SECTION=1` prevents Emscripten from
stripping the merged section. `$(WasmEmitProducersSection)=false` disables the .NET runtime
contribution.

Full repository builds link the prebuilt runtime before its pack exists. `WasmApp.InTree.targets`
therefore generates an equivalent intermediate source; shipped workload targets consume only the
runtime-pack source.

Native links pass `--build-id`. Runtime-pack modules keep that ID when copied into applications,
while an application relink creates a new file and a new ID. Emscripten and Binaryen preserve the
linker ID through post-link transformations. When Binaryen emits a source map, it records the same
value as `debugId`, preserving the module/debug-information association.

## Managed Wasm writers

`WebcilWasmWrapper` writes regular Webcil metadata directly while constructing the wrapper module.

`WasmObjectWriter` owns compiler producer encoding:

- `WebCilObjectWriter` emits the producer section into final R2R Webcil, then appends its
  content-hash build ID.
- `WasmRelocatableObjectWriter` emits producer metadata into NativeAOT objects. Relocatable object
  order is significant: `producers` follows the mandatory `linking` section and precedes
  `reloc.*`. It is not entered in the linking symbol table and has no relocation bookkeeping.

The final linker merges NativeAOT object producer sections and generates the final executable's
build ID.

## Browser SDK integration

For .NET 12 and later, `Microsoft.NET.Sdk.WebAssembly.Browser.targets` enables metadata when
converting managed assemblies to Webcil. Older target frameworks retain their previous output.
Prebuilt R2R Webcil already carries writer-owned metadata and is staged unchanged.

The runtime-pack producer source is generated by `WasmEmitProducersSource` and packaged by
`Microsoft.NETCore.App.Runtime.props`. Mono and CoreCLR native relink wiring lives in
`BrowserWasmApp.targets` and `BrowserWasmApp.CoreCLR.targets`, respectively.

## Follow-up

The .NET `processed-by` and `sdk` values are not yet registered with the tool-conventions
repository.
