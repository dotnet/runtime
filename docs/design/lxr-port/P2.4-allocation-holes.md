# P2.4 - Allocation, RC holes, and recycled lines

P2.4 adds the default-off allocator substrate over P2.1 side metadata and P2.2
block ownership. It does not select an LXR collector or alter the normal
Workstation/Server allocation path.

## Dependency and source identity

The only source dependency is merged P2.2 commit
`17ac93d30d5ebc08aeda0ddf24e562d506d72230`. P2.1 already supplies the
tunable packed RC plane and atomic word visitor. P2.3 will populate real
RC/straddle state, but P2.4 can consume and validate the existing plane without
importing P2.3.

## Paper context

The paper is Zhao, Blackburn, and McKinley,
*Low-Latency, High-Throughput Garbage Collection (Extended Version)*,
arXiv:2210.17175, 1 Nov 2022.

- §§2.6 and 3.1, PDF p.5 describe 32 KiB blocks, 256-byte lines, bump
  allocation into free runs, and skipping unavailable lines.
- §3.3.1, PDF p.7 separates empty from partially reusable blocks.
- §3.5, PDF p.9 motivates low-contention issue of clean and recycled blocks.
- Table 1 (PDF p.2) reports application latency and pauses for complete
  collectors. Table 5 (PDF p.11) reports complete-collector Time/G1 ratios.
  Table 7 (PDF p.13) is LXR-only pause characterization.

The P2.4 benchmarks characterize this allocator substrate only. They are not
application latency, GC throughput, or LXR-vs-Workstation/Server results.

## Oracle decision and reachable configuration

HEAD is the single coupled allocation/hole/reuse oracle.

`304ce69d:src/plan/lxr/global.rs:99-108,917-918` sets `rc_enabled` for
LXR's Immix and LOS spaces. The live dispatcher at
`src/policy/immix/immixspace.rs:1255-1261` therefore selects
`rc_get_next_available_lines`; the normal line-mark scanner at
`:1347-1386` asserts `!rc_enabled` and is excluded.

The selected RC path at `immixspace.rs:1264-1337`:

1. obtains `RCArray::of(block)`;
2. starts at line zero when line zero is dead, or otherwise requires two
   consecutive dead lines and starts at the second, conservatively excluding
   an object's partial final line;
3. extends through the contiguous dead run, including a run ending at the
   block boundary;
4. initializes field-log state and accounts non-copy recycled lines;
5. during concurrent/final marking, fills the selected range in the local
   object-mark plane and increments each selected line's reuse byte.

`304ce69d:src/policy/immix/line.rs:320-341` defines one packed RC-array element
per line. Its width derives from line geometry, minimum RC granularity, and
`LOG_REF_COUNT_BITS`. The port uses the P2.1 spec and word visitor rather than
assuming the default two-bit layout.

`304ce69d:src/policy/immix/line.rs:138-151` shows that
`initialize_mark_table_as_marked` writes `0xff` bytes to
`LOCAL_MARK_BIT_SPEC`; it does not write the distinct `IX_LINE_MARK` plane.
`immix_allocator.rs:316-373` zeroes reusable ranges only for non-copy
allocation and advances the allocator's hole-search cursor.

HEAD owner, lock, phase, init, and deinit semantics come from
`src/policy/immix/block.rs:235-374,457-540`. Fresh zeroing comes from
`src/policy/immix/block_allocation.rs:70-95`. The reuse byte is snapshotted by
the mature-evacuation remset at `src/plan/lxr/remset.rs:1-25,35-42`; P6.4 will
consume the same generation to reject stale entries.

## Metadata

| plane | width | data coverage | demand-zero / allocation reset | purpose |
|---|---:|---:|---:|---|
| `ReferenceCount` | selectable 2/4/8 bits | 8 bytes | 0 / 0 | live/dead line view |
| `FieldUnlogged` | 1 bit | 8 bytes | 0 / source-specific | copied/mutator field-log state |
| `ObjectMark` | 1 bit | 8 bytes | 0 / source-and-phase-specific | conservative allocation liveness |
| `LineReuse` | 8 bits | 256 bytes | 0 / preserved | remset generation |

Fresh inactive blocks clear `ObjectMark`; fresh concurrent/final blocks fill
it. Inactive recycled holes preserve existing object marks. Concurrent/final
recycled holes fill the selected range only. The quiescent packed-metadata
reset operates before cursor publication while the block or dead hole is
exclusively owned. Ordinary cyclic `LineMark` remains unselected.

## Allocator and lifetime

`ImmixAllocationManager` manages one caller-supplied, block-aligned, committed
arena. The future collector space/page-resource layer owns reservation and
commit, matching the reference split. The validation hook maps real memory
through `GCToOSInterface`.

Fresh and recycled candidate cursors are atomic. P2.2 block metadata remains
authoritative: every candidate is rechecked and owner-published under
`ImmixBlockManager::TryAcquire`. There is no owner stealing. A reusable
defrag source or candidate whose state raced is skipped if the global phase
still admits the request; a real mutator/GC phase mismatch rejects the refill.
Manager shutdown is a collector-quiescent operation: no allocator may refill,
allocate, reset, or retain the manager for later use once shutdown begins.

`ImmixBumpAllocator` is per owner. Its private hot path:

1. validates `MIN_OBJECT_SIZE`, power-of-two alignment, offset, and checked
   address arithmetic;
2. aligns `(cursor + offset)` and subtracts the offset;
3. rejects an end beyond the half-open hole;
4. advances the cursor only after all checks pass.

Objects may cross lines but never a hole or block. Block-sized allocations
remain P2.5.

Fresh mutator blocks and mutator recycled holes are zeroed before their cursor
is published; GC-copy fresh blocks and recycled holes preserve their bytes.
Neighboring live bytes are always preserved. Field-log metadata is initialized
before the cursor becomes visible to its owner. Fresh object marks are cleared
while marking is inactive and conservatively filled during concurrent/final
marking. Inactive recycled allocation preserves existing object marks and
reuse bytes; concurrent/final recycled allocation fills the selected
object-mark range and increments its reuse bytes. If discovery or metadata
preparation unexpectedly fails after ownership is acquired, refill attempts
to return the block before reporting the error.

The reuse byte increments once per line handout, not once per object.
`255 -> 0` wrap is reference behavior. Non-copy recycled-line accounting is
independent of whether marking is active.

## Configuration and default path

Product and smoke sources compile only with
`CLR_CMAKE_ENABLE_IMMIX_ALLOCATION_TEST=1`. The AMD64 validation option
defaults off and fails configuration on another target architecture.

The enabled linked runtime and standalone GC export only
`GC_ImmixAllocationTest_Run`. Default Workstation/Server builds contain no
P2.4 translation unit, export, call, or per-allocation branch. The generic
side-metadata layout contains the new declaration, but normal collectors never
construct that layout.

## Validation

The direct validator compiles P2.1/P2.2/P2.4 product sources against the P2.1
OS shim. It covers:

- exact holes for 2/4/8-bit RCs, all-live/all-dead/interior/trailing/multiple
  runs, minimum-run filtering, first-dead-line exclusion, and block end;
- fresh/recycled acquisition, ownership contention, phase rejection,
  defrag-candidate skipping, reset, release, and reacquisition;
- CoreCLR minimum size, alignment/offset, exact hole end, block boundary,
  overflow, and unchanged cursor on failure;
- source-specific full-block versus selected-hole zeroing and preservation of
  adjacent live or copy bytes;
- inactive versus concurrent/final object-mark publication over every logical
  entry, adjacent-mark preservation, `255 -> 0` reuse wrap, neighboring
  counters, and recycled accounting;
- missing metadata, invalid inputs, and explicit 32-bit fail-close.

Windows x64 and Linux x64 run the full validator. Windows x86 runs the
fixed-address fail-close. Windows ARM64 compiles exact product translation
units. Linked and standalone Workstation/Server runtime smoke executes on
Windows and Linux x64.

## Performance evidence

The native BenchmarkDotNet harness uses persistent workers at 1, 4, and 16
threads and fixed 32-operation batches. It measures fresh, recycled,
concurrent-recycled, RC scan, and a fixed 90%-recycled long-lived-cache mix.

The declared run is three launches, eight warmups, and twenty measured
iterations. Fresh and recycled duplicate A/A ratios must each be in
`[0.90,1.10]`. Sixty-four RC scans must cost at least 1.5x one scan, and the
injected-delay arm must cost at least 1.25x normal recycled allocation.
Idle persistent workers block outside measured batches so worker counts do not
contaminate one another. Absolute rates are characterization only.

Raw rows, exact source/runtime/native identities, default-path evidence,
reviews, and archive-gate results live under `P2.4/raw/` in the evidence-only
commit.

## Evidence topology and limitations

The non-raw source commit is parented directly by P2.2. Its only child is the
evidence commit, whose changed paths are all under `P2.4/raw/`. The committed
gate audits a short-path `git archive` extract, verifies every archived entry,
and requires controlled source, behavior, evidence, and benchmark
perturbations to fail for their intended reason.

This remains default-off substrate. There is no complete LXR collector, real
P2.3 RC producer, LOS, scheduler, RC packet processing, SATB, sweep scheduler,
or evacuation integration.
