# P1.2 - generic x64 slot-log write barrier

## Scope

P1.2 implements `WriteBarrierShape::SideMetadataFieldLog` for CoreCLR AMD64. The capability is
collector-neutral: the runtime knows how to locate one metadata bit per destination slot, decide
whether work is required, and call a collector callback before the field is overwritten. It does not
name or encode LXR reference-count state.

Windows x64 uses MASM and System V x64 uses GAS. The selected family includes a software-write-watch
variant. The existing card-table variants remain the default and retain their existing helper address,
selection rules, and machine code.

The implementation also closes the ordinary reference-store funnels that bypass the JIT scalar
helpers:

- null and frozen-reference stores;
- checked and unchecked field/array/byref stores;
- VM and reflection stores;
- atomic exchange and compare-exchange, including failed-CAS pre-logging;
- bulk and overlapping reference copies, including mixed scalar/reference value types;
- reference and mixed-value-type `Array.Clear`/`Span.Clear`;
- collectible MethodTable to LoaderAllocator logical edges.

## Prerequisite

The exact P1.1 chain is preserved:

```text
7199d2b08c2 -> 378038fdbb4 -> 110a467c07f -> f3f02c558d3
             -> d909ec829b0 -> c34445f3101
```

P1.2 extends the fixed P1.1 5.9 tail without changing its offsets. Interface 5.10 appends:

```cpp
WriteBarrierRangeSlowPath write_barrier_range_slow_path;
WriteBarrierDependentEdgeSlowPath write_barrier_dependent_edge_slow_path;
```

Interface 5.11 appends:

```cpp
WriteBarrierEpochReset write_barrier_epoch_reset;
```

A 5.9 or 5.10 collector remains layout-compatible. Production side-metadata activation requires the
complete 5.11 tail; incomplete requests fail with `Unsupported` before any unknown field is read or
any helper/global is changed.

P1.3 subsequently raises production side-metadata activation to the complete 5.12 tail so the runtime
can safely scan the collector-declared metadata storage by native words. The 5.9-5.11 offsets recorded
here remain unchanged.

### B03 deviation

The declared oracle remains PLDI, but ledger B03 requires the .NET realization to use HEAD's protocol:

- load old before claiming metadata;
- one atomic compare-exchange on the log bit;
- `SeqCst` ordering;
- no separate PLDI `RC_LOCK_BITS`.

The validation consumer implements the claim as a 32-bit compare-exchange over the aligned word that
contains the metadata byte. Unrelated bits and bytes are preserved.

## Descriptor and semantics

For destination address `D`:

```text
metadata byte = metadata_base + (D >> (granularity_shift + 3))
metadata bit  = (D >> granularity_shift) & 7
```

`metadata_base` is already biased by the collector. `granularity_shift`, its `+3` byte shift, the
base, polarity, slow-stub target, and optional write-watch table are patched into the selected template
during initialization.

The scalar callback is:

```cpp
void slow_path(Object** destination, Object* old_reference, Object* proposed_new_reference);
```

For conditional atomic writes, the proposed value need not commit. The exact binding invokes the
pre-barrier before CAS and may log a failed CAS. A consumer must not infer a successful increment from
the proposed value.

The callback and range/dependent-edge callbacks are no-GC, no-throw, non-blocking,
allocation-free, cooperative-mode operations. They must not re-enter a reference store.

`LOG_REF_COUNT_BITS` remains collector-owned. Validation derives max as `(1 << bits) - 1` for 2, 4,
and 8 bits. Increment saturates at max; decrement is a no-op at zero and max. Neither the descriptor
nor the assembly hardcodes two bits or max three.

## x64 instruction shape

### Windows

Input:

- `RCX`: destination;
- `RDX`: proposed new reference.

The copied leaf template:

1. loads old from `[RCX]`;
2. shifts the full 64-bit destination by the patched byte shift;
3. loads one metadata byte from the patched biased base;
4. XOR-normalizes polarity so one always means work;
5. exits on a normalized zero byte;
6. extracts the destination bit with 64-bit address arithmetic and `bt`;
7. stores and returns if the bit is clear;
8. otherwise loads an absolute patched slow-stub address and tail-jumps.

No call, stack adjustment, relative branch to external code, or RIP-relative external reference is
present in the copied body.

The static slow stub is a `NESTED_ENTRY` outside the copied range. It reserves 0x38 bytes, including
the 32-byte Windows shadow area, maps `(destination, old, new)` to `RCX/RDX/R8`, calls the collector,
restores destination/new, performs the store, and returns to the managed caller.

### System V

The GAS template is instruction-equivalent with:

- `RDI`: destination;
- `RSI`: proposed new reference.

The slow stub reserves 0x18 bytes, maps arguments to `RDI/RSI/RDX`, and uses repository unwind macros
to emit CFI. The System V clobber probe destroys all volatile integer registers, XMM/YMM/ZMM state,
and K1-K7 where supported.

### Register contract

Side metadata selects P1.1's immutable Standard ABI before compilation. The JIT uses:

- full ABI volatile integer, floating/vector, and mask kill sets;
- `BuildKills`, including upper-vector save/restore;
- Windows outgoing argument space.

R2R and NativeAOT are rejected because their images embed the Specialized contract and null/frozen
barrier elisions.

## Initialization and failure

The request is rejected before managed execution for:

- non-AMD64 targets;
- interface older than complete 5.11;
- null callbacks/base;
- invalid shift or polarity;
- ReadyToRun enabled;
- copied write barriers disabled;
- portable helpers/entrypoints;
- debug barrier verification conflict;
- an already-observed incompatible JIT mode.

There is no fallback to CardTable after a non-default request.

Tiering and OSR see the same immutable flags and helper address. Write-watch transitions map only
between the slot-log and write-watch slot-log templates.

## Complete store surface

The JIT receives a semantic flag that old values are required. Assertion propagation, late GC-info
classification, and atomic intrinsic selection all honor it. The Standard ABI bit is accepted as the
compatibility signal because P1.1 side metadata is the only Standard-ABI shape.

`RuntimeHelpers.RequiresOldValueWriteBarrier` is folded by both compilers from the immutable startup
mode. The JIT removes the untaken branch. The interpreter emits `ldc.i4 0` for CardTable and
`ldc.i4 1` for slot logging; its current IR retains the constant conditional branch, but performs no
process-state read at execution time.

Secondary funnels use one pre-barrier decision:

- `SetObjectReferenceUnchecked` logs before `VolatileStore`;
- `COMInterlocked::{Exchange,CompareExchange}Object` logs before the RMW, including failed CAS;
- reference-only ranges invoke the range callback once before any forward/backward copy or clear;
- a null range source means every proposed new reference is null, so clear never dereferences source;
- typed JIT copies are decomposed by their exact GC layout, including large structs;
- dynamic value-type copies and clears enumerate the MethodTable GC descriptor before writing;
- software write watch is dirtied by every selected VM scalar/range/layout path;
- the existing post-card path is used only when slot logging is not selected;
- collectible MethodTable updates report old/new LoaderAllocator objects through the dependent-edge
  callback; non-collectible UOH MethodTable stores report no logical edge.

Every callback for a chunk observes its source/destination references before the first copy write.
Forward and backward overlap preserve memmove semantics, and managed chunking polls only after a
fully logged and copied/cleared chunk. Non-reference words in mixed structs are copied or zeroed
atomically but are never reported as managed references.

## Validation

### Windows x64

- clean main baseline: `clr+libs+host`, zero warnings/errors;
- x64 and x86 layout checks: 15/15 each plus 5/5 aggregate initialization checks;
- P1.1 focused integration: 8/8;
- P1.2 selected smoke: built-in and standalone, Workstation and Server;
- both metadata polarities;
- `DOTNET_JitStressRegs=8` and `DOTNET_GCStress=0xC`;
- null/frozen, VM/reflection, exchange, failed CAS, bulk, and overlapping copy;
- reference and mixed-struct `Array.Clear`, mixed-struct `Span.Clear`, and exact-layout typed copy;
- one range callback for reference copy/clear/overlap, no range callback for mixed layouts, and no
  callback/source read for empty ranges;
- zero dependent-edge callbacks for non-collectible UOH allocations and one for a collectible
  RunAndCollect array type;
- exact `34 A5` polarity encoding at both MASM and GAS patch labels;
- byte-zero, mixed-byte bit selection, same-slot contention, and eight bits in one byte;
- built-in and standalone metadata epoch reset across a finished full GC;
- live Vector128/256/512 plus destructive K1-K7 callback;
- managed null-destination fault mapping;
- CardTable/slot-log interpreter IR constants `0`/`1` with no execution-time mode opcode;
- fail-closed matrix: 7/7.

### Linux x64

Ubuntu 22.04 under WSL2 built the exact working tree on ext4 using Clang 14. The GAS product and the
System V clobber probe execute:

- built-in and standalone GC;
- Workstation and Server;
- both polarities;
- all scalar/range/contention and register-state checks.
- built-in and standalone epoch re-claim after a finished full GC.
- interpreter-only mixed-reference copy and clear with compile-time `ldc.i4` mode selection;
- async-continuation compaction source/disassembly audit.

The final logs report:

```text
PASS: field/array helpers, integer, object, Vector128,
      slot-log fast/slow/contention, Vector256, Vector512, opmask clobber;
      callback delta 160006
```

### Unsupported targets

Windows x86 builds the 5.11 layout validator but rejects the shape. NativeAOT keeps its fixed image
contract and rejects the non-default shape. Other architectures retain CardTable and do not compile a
slot-log template.

## Performance

All performance runs use the same Windows x64 host and no-PGO Release Core_Root pair. ReadyToRun and
tiering are off. These numbers are local evidence, not paper targets.

### Barrier-only microbenchmark

BenchmarkDotNet 0.16.0-preview.1, 3 launches, 8 warmups, 20 measured iterations, 16 unrolled stores:

| arm | field mean | array mean |
|---|---:|---:|
| stock CardTable | 3.033 +/- 0.0021 ns | 4.092 +/- 0.0034 ns |
| slot slow + empty callback | 14.39 +/- 0.015 ns | 16.12 +/- 0.031 ns |
| slot slow + counting/card callback | 21.63 +/- 0.022 ns | 23.55 +/- 0.061 ns |
| claimed-bit slot fast path | 2.161 +/- 0.0050 ns | 3.822 +/- 0.0144 ns |

The claimed-bit isolated field/array paths are 0.71x/0.93x stock. The slow rows are upper bounds for
callback-heavy epochs.

### Corrected range callback

The follow-up benchmark compares an exact `fa1c9cef001` no-PGO build against the corrected no-PGO
slot-log runtime with identical built-in validation settings. BenchmarkDotNet used 3 launches,
8 warmups, and 20 measured iterations. Results are normalized per reference slot:

| operation | pre-fix mean | corrected mean | ratio |
|---|---:|---:|---:|
| 16-reference `Array.Copy` | 9.025 ns | 7.816 ns | 0.8660x |
| 16-reference `Array.Clear` | 8.339 ns | 7.873 ns | 0.9441x |

Replacing per-slot VM helper re-entry with one range callback improves copy by 13.4% and clear by
5.6% in this isolated validation consumer.

The original scalar field/array measurements remain valid: these corrections do not change their
selected instruction sequence, and the new `A5` patch sentinel is replaced by the same runtime
polarity value before execution. The end-to-end harness contains no `Array.Copy`, `Array.Clear`,
`GC.AllocateArray`, or interpreter scenario, so its recorded paths are unaffected. Dependent-edge
noise removal is a correctness-only change on collectible-aware UOH allocation. Interpreter IR
shows `ldc.i4 0` for CardTable and `ldc.i4 1` for slot logging, replacing the prior execution-time
mode read; no timing claim is made for interpreter dispatch noise.

### End-to-end

The existing zero-package harness ran five paired, interleaved invocations per arm with 1 second
warmup and 5 seconds steady state. Every run confirmed Workstation/Server identity and emitted the
deterministic completion marker.

Claimed-bit low-allocation compute had zero collections in every invocation:

| GC | stock ops/s | slot fast ops/s | ratio | paired range |
|---|---:|---:|---:|---:|
| Workstation | 2,762,219 | 2,545,396 | 0.922 | 0.887-0.944 |
| Server | 2,720,517 | 2,537,628 | 0.933 | 0.919-0.942 |

The 7-8% difference is below the previously demonstrated 8.35% host resolution floor, so it is
reported as unresolved rather than a proven regression. Unlike the microbenchmark, this scenario also
pays Standard-ABI spill/code-size effects around 64 stores per operation.

Allocation churn uses `claimBits=0` because the validation consumer deliberately has no production
epoch-reset policy. It is a slow-path upper bound:

| GC | stock ops/s | slot slow ops/s | throughput ratio | allocation-rate ratio |
|---|---:|---:|---:|---:|
| Workstation | 142,583 | 79,110 | 0.555 | 0.559 |
| Server | 323,462 | 119,761 | 0.370 | 0.370 |

This does not predict an LXR collector. It quantifies the cost if every store reaches a counting/card
callback.

The validation consumer also ran claimed-bit allocation churn with a stop-the-world full-table reset
at every finished GC:

| GC | stock ops/s | claimed-bit ops/s | ratio | allocation-rate ratio |
|---|---:|---:|---:|---:|
| Workstation | 145,047 | 7,686 | 0.053 | 0.061 |
| Server | 325,769 | 33,742 | 0.104 | 0.109 |

This is evidence against using a whole-heap metadata clear as the production epoch protocol. The
generic barrier does not prescribe reset mechanics; the collector needs a sparse/generational epoch
design.

## Limitations

- The validation consumer composes card marking. The generic runtime barrier itself is card-agnostic.
- The validation consumer resets its whole metadata table before mutators resume after a finished GC.
  This is correct but deliberately unoptimized; a real collector owns a sparse/generational epoch
  design.
- The end-to-end runs use the unpinned default heap, not the future LXR 1.3x/2x/6x calibrated matrix.
- The paper's 1.6% figure is a geomean versus no-barrier Immix and lies inside its own noise floor; it
  is not a pass threshold here.
- Application-observed latency remains the future collector acceptance signal. Pause data is
  characterization, not a win condition.
