# P2.1 — Fixed-address side metadata framework

**Status:** implemented and validated. The implementation base is
`2f49bf4340822439a031d91786398a379668b25e`, the P1.6 `lxr` tip.

P2.1 adds the collector-owned metadata substrate needed by later LXR phases. It provides fixed
address-to-metadata mapping, exact reservation and demand-zero commitment, atomic bit/sub-byte/
byte/word operations, selectable sticky reference counts, bounded bulk-word reads, and quiescent
bulk reset/copy. It does not allocate Immix objects, process RC increments/decrements, trace SATB,
sweep, evacuate, install forwarding pointers, or add a managed/GC-EE/JIT API.

## Paper context

The paper is Zhao, Blackburn, and McKinley, arXiv:2210.17175, **Extended Version,
1 November 2022**.

- Figure 1 (PDF p.3) and §3.2.1 (PDF p.6) describe two-bit side RCs `0`, `1`, `2`, and sticky
  `3+`. One count covers 16 OpenJDK bytes; four RC bytes cover one 256-byte line, or 1.5625% for
  RC alone.
- §5.4 (PDF p.14) reports 2.9% and 3.4% penalties for four- and eight-bit counts in that
  implementation. These are context, not .NET thresholds.
- §§2.6/3.1 (PDF p.5) use 32-KiB blocks and 256-byte lines.
- §§3.2.2/3.4 (PDFs pp.7–9) place mark bits and one unlogged bit per pointer field in side
  metadata.
- Table 1 (PDF p.2) shows longer LXR GC pauses than G1 at every reported percentile but lower
  application query tails. Table 7's p50/p95 values (PDF p.13) are LXR-only; there is no G1 p95
  comparison.
- Table 5 (PDF p.11) reports Time/G1 `0.97`, `0.96`, and `1.01` at 1.3x, 2x, and 6x heaps.
- Figure 3/Table 7 (PDFs pp.9/13) report a 1.016 field-barrier geomean against no-barrier
  full-heap Immix, not G1. The approximately +/-3% noise interpretation is external.
- Compressed pointers, class unloading, and weak references were disabled (§4, PDF p.9).

The reference code is a semantic oracle. No Java/MMTk timing is used as a performance baseline.

## Metadata inventory

`P2.1/metadata-specs.json` is the structured authority for the 14 allocated planes, both oracle
identities, address-space anchors, widths, granularities, ordering, and consumer ownership.

The allocated planes cover:

- valid-object/allocation state;
- selectable 2/4/8-bit RCs, default two bits;
- field-unlogged state;
- object mark state;
- RC straddle lines;
- block mark/state, defrag/hole count, and log state;
- nursery promotion and phase epoch;
- line and LOS-page reuse;
- block owner and block-in-use.

Forwarding state is not duplicated. P1.6 owns the two-bit header transition on supported 64-bit
CoreCLR. The forwarding pointer remains P6 work. SATB uses the shared old-reference/decrement
buffer rather than a separate P2.1 plane. Ordinary Immix cyclic line marks are not selected by
LXR. Declarations with no selected consumer are recorded but not allocated.

HEAD changes RC granularity from PLDI's 16 bytes to its core minimum-object granularity of
8 bytes (`304ce69d:src/util/rc.rs:13-34`). CoreCLR object starts are also 8-byte aligned on the
supported 64-bit target, so P2.1 uses an 8-byte address lattice. It does not claim that the
paper's 1.5625% RC-only overhead transfers to .NET.

## Fixed layout and mapping

The selected topology pins HEAD's 47-bit anchors:

```text
global base = 0x00000c0000000000
local base  = 0x00004c0000000000
data limit  = 2^47
```

For `m = log2(bits/value)`, `b = log2(data bytes/value)`, and address `A`, sub-byte/byte
metadata uses:

```text
entry               = A >> b
entries_per_byte    = 1 << (3 - m)
metadata_byte_index = entry >> (3 - m)
field_index         = entry & (entries_per_byte - 1)
bit_shift           = field_index << m
mask                = ((1 << (1 << m)) - 1) << bit_shift
metadata_byte       = spec_base + metadata_byte_index
```

For values wider than one byte:

```text
entry               = A >> b
bytes_per_value     = 1 << (m - 3)
metadata_byte_index = entry << (m - 3)
metadata_address    = spec_base + metadata_byte_index
```

One complete 47-bit spec range occupies:

```text
2^(44 - b + m) bytes
```

Following specs are native-word aligned. The RC plane reserves the full 8-bit range even when
two or four bits are active, so changing `lxr_rc_bits_{2,4,8}` never moves a later plane.
Construction fails if global metadata reaches the local anchor, local metadata reaches `2^47`,
an active range exceeds its reservation, or checked arithmetic overflows.

The native-word location is:

```text
word_address = align_down(metadata_byte, sizeof(uintptr_t))
byte_in_word = metadata_byte - word_address
word_shift   = little endian
             ? byte_in_word * 8 + bit_shift
             : (sizeof(uintptr_t) - byte_in_word - value_bytes) * 8 + bit_shift
word_mask    = logical_mask << word_shift
```

The validator executes little-endian accesses and directly checks both shared little- and
big-endian formula helpers.

## Reservation and lifetime

`GCToOSInterface::VirtualReserveAt` is a generic internal static operation:

- exact page-aligned address;
- inaccessible reservation;
- never replace an existing mapping;
- return the requested address or null.

Windows uses exact-address `VirtualAlloc`/`VirtualAllocExNuma`. Unix uses
`MAP_FIXED_NOREPLACE` where available and otherwise accepts only an exact returned hint; a
different mapping is immediately removed. `MAP_NORESERVE` is requested when supported.
WebAssembly returns unsupported because linear memory cannot implement fixed, non-replacing
virtual reservations.

This adds no `IGCHeap`, `IGCToCLR`, JIT-EE, managed, or versioned binary contract.

Initialization reserves the complete global and local envelopes. A partial failure releases only
the range acquired by that attempt. Each manager enables an explicit spec mask; metadata pages for
those planes are committed before the corresponding data range is registered. The P1 field-log
test consumer enables only `FieldUnlogged`, while the complete LXR layout enables all selected
planes. Commitment is monotonic and demand-zero for the manager lifetime; teardown releases both
exact envelopes only after caller quiescence.

The manager merges owned data intervals. Checked scalar and bulk operations reject addresses or
ranges outside those intervals, ranges beyond `2^47`, overflow, invalid widths/values, and
incompatible copies.

## Atomic and bulk contract

All packed updates operate on naturally aligned native words. A CAS retry recomputes from the
newly observed word and preserves every non-target bit. There are no unaligned atomics, byte/word
mixed-size atomic overlaps, or plain load/modify/store updates.

The API provides:

- logical load/store/CAS;
- fetch-or/fetch-and;
- wrapping add for explicit epoch/reuse counters;
- sticky RC increment;
- RC decrement that refuses zero and the sticky maximum;
- safe byte and native-word operations through the same masked machinery;
- bounded word visitors;
- quiescent range reset and compatible-plane copy.

Selected consumer orderings are:

- relaxed logical operations for RC and object mark;
- sequential consistency for field logging, VO, block state/ownership, and forwarding-compatible
  publication.

The current CoreCLR CAS primitive can be stronger than a requested relaxed RMW. It is never weaker.
Concurrent bulk reads are atomic per word, not a global snapshot. The monotonic field-log epoch may
produce an unnecessary slow path from a stale read but cannot skip required work. Reset/copy are
quiescent-only; boundary words still use CAS so an accidental neighboring update cannot be
clobbered.

## Microbenchmarks

The BenchmarkDotNet harness invokes native fixed-size batches and normalizes by
`OperationsPerInvoke`, keeping the managed/native transition outside individual operation cost.
The launcher changes to the benchmark project directory for BenchmarkDotNet project discovery and
restores the caller's directory in `finally`; a dedicated control invokes it from an unrelated
temporary directory with an explicit repository root.
It characterizes:

- mapping plus load and a precomputed-location lower bound;
- bit store;
- 2/4/8-bit RC updates;
- byte updates;
- sequential and sparse bulk-word reads;
- 4-KiB, 64-KiB, and 1-MiB reset;
- fixed-envelope reserve plus first page commitment;
- same-word and separate-cache-line two-thread updates;
- an eight-extra-CAS sensitivity control.

The declared run is three launches, eight warmups, and twenty measured iterations on the same
machine/runtime. The A/A mapping control must remain within `[0.90, 1.10]`; the extra-CAS arm must
be at least 1.5x the normal bit store. New-path times are characterization, not a paper comparison
or an arbitrary acceptance threshold.

## Boundary

P2.1 ends at reusable storage, mapping, atomicity, lifetime, and proof. Later phases own:

- P2 allocation and Immix state transitions;
- P3/P4 RC work and sweeping;
- P5 SATB and cycle collection;
- P6 forwarding pointer placement, copying, and redirection;
- pin-aware evacuation and the risk rows for weak references, class unloading, and compressed
  references.
