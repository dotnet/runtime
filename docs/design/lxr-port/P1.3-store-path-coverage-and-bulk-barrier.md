# P1.3 - store-path coverage and family-level bulk barrier

## Scope and prerequisite

P1.3 starts from fork `main` commit
`70207d8de0a347fea0665fb002d17b75c05a2e0c`. That squash commit has tree
`419b5e0752bad6f1cd7913e2413ca48662d3edb0`, byte-identical to the final P1.2
tip `169144077909822fd3c4726e080298495fa5534f`.

P1.2 already made the generic x64 family correct for scalar, checked,
unchecked, null, frozen, atomic, VM, reflection, all-reference range,
mixed-layout, interpreter, and collectible dependent-edge writes. P1.3 does
not replace those contracts. It adds the missing family-level bulk early-out,
layout-aware JIT helpers, and the corresponding store-path proof.

The implementation remains collector-neutral. Runtime types and entry points
describe side metadata, destination layouts, and bulk operations; none names
LXR or interprets reference counts.

Reference-count width remains collector-owned:

- `df8d30a3:src/util/rc.rs:30-43`;
- `304ce69d:src/util/rc.rs:13-26`.

`LOG_REF_COUNT_BITS` selects exponents 1, 2, or 3, default 1; the derived
`REF_COUNT_BITS` is therefore 2, 4, or 8, default 2, with saturation at
`(1 << REF_COUNT_BITS) - 1`. The runtime bulk operation reads only field-log
metadata and is independent of that width.

## Interface 5.12

GC interface minor 12 appends, after the complete 5.11 tail:

```cpp
struct WriteBarrierBulkScanParameters
{
    uint8_t* metadata_start;
    size_t metadata_size;
};
```

The earlier prefix and offsets are unchanged. Layouts are:

| item | x64 | x86 |
|---|---:|---:|
| complete 5.8 prefix | 80 | 44 |
| 5.9 side-metadata tail start | 80 | 44 |
| 5.10 range callback | 112 | 64 |
| 5.11 epoch reset | 128 | 72 |
| 5.12 bulk-scan tail | 136 | 76 |
| complete structure | 152 | 84 |

SideMetadataFieldLog activation requires the complete 5.12 tail:

- `metadata_start` is non-null and native-word aligned;
- `metadata_size` is nonzero and a native-word multiple;
- `metadata_start + metadata_size` does not overflow;
- the storage covers every metadata byte mapped from the managed heap;
- claims transition atomically from work to claimed while mutators run;
- reset occurs only while mutators are suspended.

Malformed or pre-5.12 family requests fail with `Unsupported` before helper
or barrier-global mutation. CardTable compatibility remains zero-initialized
and unchanged. ReadyToRun, NativeAOT, non-AMD64, portable helpers, and portable
entrypoints remain fail-closed.

## Native-word scan

For nonempty destination byte range `[D, D + N)` and metadata granularity
shift `G`:

1. Validate that the complete range is in the managed heap and does not
   overflow.
2. Compute the first and last represented metadata bytes and bits from the
   existing biased base.
3. Align the actual metadata addresses down to `sizeof(uintptr_t)`.
4. Require both words to lie in the 5.12 storage.
5. Build exact first/last masks; combine them when both endpoints share a
   word.
6. Load each aligned native word once.
7. Normalize work bits:

   ```text
   work = raw   // WorkWhenBitIsSet
   work = ~raw  // WorkWhenBitIsClear
   ```

8. Return slow on the first active work bit; otherwise return all-claimed.

The scan has three results:

- CardTable: the family is not selected;
- AllClaimed: the family is selected and callbacks can be skipped;
- NeedsSlowPath: exact callbacks must run.

It never claims a bit. The existing SeqCst per-slot CAS still decides the one
successful logger. Claims are monotonic within a mutator epoch, so a stale
word read can only cause an unnecessary slow path; it cannot skip required
work. Stop-the-world reset cannot race.

For mixed layouts, the word scan conservatively covers the destination byte
range. A scalar slot may cause a harmless slow fallback. Only the exact
`CGCDesc` walk reports references.

## Operation semantics

- All-reference copy invokes the existing range callback once only when the
  scan reports slow.
- Clear retains null-source meaning and never dereferences a source.
- Mixed copy and clear retain exact descriptor enumeration.
- Fill treats one stable source value as the template for every destination
  element and enumerates only its GC slots.
- Every callback for a chunk completes before its first write.
- Forward and backward overlap retain memmove order.
- Identical source/destination and empty ranges are no-ops.
- Empty ranges read no source or metadata, invoke no callback, and dirty no
  software-write-watch byte.
- A nonempty all-claimed write still dirties software write watch.
- Managed chunking polls only after a fully classified, logged, and written
  chunk.
- Throwing cast/box array copies remain element-wise, so each committed store
  is barriered and existing partial-progress guarantees remain intact.

## JIT and CoreLib

Two helper IDs are appended without renumbering existing helpers:

```text
CORINFO_HELP_BULK_WRITEBARRIER_WITH_LAYOUT
CORINFO_HELP_BULK_WRITEBARRIER_CLEAR_WITH_LAYOUT
```

They target managed CoreLib value-class copy/clear wrappers with an embedded
or runtime-looked-up class handle. Each wrapper retains tracked source and
destination byrefs, divides one value into at most the existing
`BulkMoveWithWriteBarrierChunk` (1 KB Debug, 16 KB Release), calls a bounded
InternalCall, and executes `Thread.FastPollGC` only after the chunk is fully
barriered and written. The InternalCall receives the whole element size plus
the exact chunk offset and size. It binary-searches the sorted `CGCDesc`
series, enumerates only series intersecting that chunk, and then performs the
copy or clear.

Only value-class layouts are eligible: their runtime descriptors use the
unboxed, `OBJECT_SIZE`-adjusted coordinate convention consumed by the helper.
Stack-allocated reference-class layouts retain exact non-helper lowering, and
the shared runtime chunk helper asserts the actual non-array descriptor
contract; large reference-class `MemberwiseClone` remains a supported caller.
In old-value mode,
eligible optimized layouts larger than 16 KB always select the bounded helper
instead of expanding as LIR. Large volatile typed copies use the same helper
surrounded by the JIT's established store/load memory-barrier nodes. Custom
value-class slices that preserve an aligned subset of a runtime type's GC
layout retain that type's descriptor, value-class identity, and the slice's
byte offset as part of their immutable JIT layout identity. The helper
enumerates in descriptor coordinates and maps each reference back to the
current chunk. Truly descriptor-less JIT layouts retain the exact per-slot
fallback without an invalid heap/non-heap assertion.

For layouts at or below 16 KB, minopts/cold code with more than one reference
uses the helper, while optimized code uses it at 128 references. Four-, 16-,
and 64-reference helper pilots all lost to P1.2's per-slot code. The
64-reference final per-slot method is 1,419 bytes and the P1.3/P1.2 runtime
ratio is 0.9993. Therefore 128 is explicitly a code-size policy, not a
measured speed crossover. The raw 4/16/64 rows and normalization are in
`P1.3/raw/layout-helper-pilots.csv`.

The deterministic regression control uses a 48 KB mixed InlineArray with
4,096 references. Before the bound, optimized copy and clear generated
106,418 and 75,742 bytes. The bounded implementation generates one helper
call and 49/44 bytes; its volatile copy generates one helper call and 44
bytes. Exact binary/disassembly hashes are in
`P1.3/raw/layout-helper-codegen.csv`.

A second control covers the runtime-async heap-slice path that originally
exposed the handle-less-layout assertion. An optimized runtime-async method
awaits a 49,160-byte mixed result whose GC slice starts at byte 8. Before
descriptor-offset propagation its Tier0 body expanded to 119,387 bytes. The
bounded body is 689 bytes and contains one layout-clear helper with descriptor
offset 8 and slice size `0xBFF8`; the functional xUnit run passes 1/1.

A stack execution/codegen control materializes a 128-reference class in a
1,128-byte frame under old-value mode. Final Release code is 414 bytes with
zero object-allocation helpers and zero layout helpers, confirming that stack
allocation and execution remain correct. It is not behavioral proof of the
value-class eligibility gate: that contract is verified structurally at its
single JIT source site, by exact-cardinality perturbation, and by independent
call-path review.

Separately, a genuine shared-helper regression executes a 48 KB
reference-class `MemberwiseClone` through 1 KB Debug/Checked and 16 KB Release
chunks. Windows Release/Checked and exact Linux Debug rows record final passes
and exact runtime/CoreLib identities in
`P1.3/raw/reference-class-codegen.csv`.

The helpers are ordinary platform-ABI calls. Normal call lowering, LSRA kill
sets, GC byref tracking, outgoing arguments, and unwind information apply.
There is no new `ICorJitInfo` virtual method.

`Span<T>.Fill` adds a CoreCLR-only branch for reference-containing `T`. The
JIT folds it away when old values are not required. `Array.Fill` inherits the
exact-type Span path; covariant arrays retain element-wise checked stores.

## Store-path ledger

| path | current P1.3 disposition |
|---|---|
| JIT field/array/static checked and unchecked stores | existing scalar family helpers |
| null and frozen-reference values | old-value flag prevents elision |
| `ASSIGN_BYREF` / ensure-nonheap helper names | not present; managed byrefs cannot be heap fields |
| typed `cpobj` / `stobj` | bounded layout helper for large typed layouts (including volatile), exact per-slot fallback otherwise |
| stack-allocated reference-class layouts | never use value-class layout helpers; exact stack/object lowering |
| typed `initobj` | layout clear helper when eligible, exact per-slot fallback otherwise |
| raw `cpblk` / `initblk` / `Unsafe.CopyBlock` | raw-byte unsafe contract, not a typed reference operation |
| all-reference Array/Span/Buffer copy | one range callback or all-claimed skip |
| Array/Span clear | null-source range callback or all-claimed skip |
| Span/Array fill | repeated-value layout helper |
| mixed value classes | conservative scan plus exact `CGCDesc` fallback |
| MemberwiseClone and array clone | shared all-ref/layout helpers |
| boxing, unboxing, nullable, Array.SetValue | shared layout helpers |
| VM and reflection scalar writes | `SetObjectReferenceUnchecked` and scalar pre-barrier |
| exchange and compare-exchange | pre-barrier before RMW, including failed CAS |
| LoaderAllocator direct CAS | pre-barrier before RMW |
| exception fields and keepalive arrays | scalar/range shared funnels |
| interpreter scalar and value-class stores | scalar/layout shared funnels |
| interpreter continuation compaction | coarse scan plus exact streamed-layout walk |
| collectible MethodTable edge | dependent-edge callback only for collectible types |
| GC handle table | outside the managed heap; owned by `IGCHandleManager` and `HndWriteBarrier` |
| software write watch | scalar/range/layout/fill and all-claimed paths compose it |
| tiering and OSR | immutable flags and helper table |
| ReadyToRun and NativeAOT | fail closed for the nondefault family |

## Performance

The microbenchmarks use the same Windows x64 Hyper-V host, SDK
`11.0.100-preview.6.26359.118`, no-PGO Release Core_Roots, ReadyToRun and
tiering disabled, 3 launches, 8 warmups, and 20 measured iterations. The
three arms are preserved P1.2 stock CardTable, corrected final P1.2 family,
and P1.3 family. Values are normalized per managed reference:

| operation | stock | P1.2 family | P1.3 family | P1.3 / stock | P1.3 / P1.2 |
|---|---:|---:|---:|---:|---:|
| 16-reference Array.Copy | 0.7092 ns | 7.8105 ns | 1.3286 ns | 1.8734 | 0.1701 |
| 16-reference Array.Clear | 0.3963 ns | 7.8350 ns | 1.1858 ns | 2.9922 | 0.1513 |
| 16-reference Span.Fill | 3.5765 ns | 3.0142 ns | 1.8989 ns | 0.5309 | 0.6300 |
| 64-reference mixed struct copy | 0.3798 ns | 2.1536 ns | 2.1522 ns | 5.6667 | 0.9993 |
| 4,096-reference/48 KB mixed struct copy | 0.2842 ns | 5.1801 ns | 7.9092 ns | 27.8297 | 1.5268 |
| 4,096-reference/48 KB mixed struct clear | 0.4497 ns | 5.0210 ns | 8.3154 ns | 18.4910 | 1.6561 |

The family metadata early-out improves final P1.2 Array.Copy by 83.0%,
Array.Clear by 84.9%, and Span.Fill by 37.0%. The optimized 64-reference
struct path remains per-slot and is equal to P1.2 within 0.1%; the family
layout helper is a minopts/code-size mechanism, not a claimed speedup.

The bounded 48 KB helper is also a correctness/code-size mechanism, not a
speedup: it is 52.7% slower than P1.2 per-slot copy and 65.6% slower for clear
in the claimed epoch. The tradeoff removes 106 KB/76 KB generated methods and
unbounded compile-time growth while adding GC-safe polling. Full distributions
are retained in `P1.3/raw/large-layout-benchmark.csv`.

The P1.3 Span.Fill distribution was multimodal; its median was 1.6740 ns and
the 99.9% confidence interval around the mean was wider than the other rows.
It remains faster than both comparison arms, but the raw distribution is
retained rather than summarized as a precise stable speedup.

An exact no-PGO rebuild of product commit `f2315e8929e` was rerun separately
for build identity. Its means were 1.5590, 1.1230, 1.8070, and 2.1650
ns/reference respectively. Array.Copy remained multimodal (Q1-Q3
1.3090-1.6010 ns); the other three exact-commit runs had narrow
distributions. Binary hashes for all three arms are shipped in
`P1.3/raw/runtime-identities.csv`.

The existing zero-package harness ran 20 paired, interleaved, 8-worker,
5-second claimed-epoch throughput samples:

| GC | stock ops/s | P1.3 family ops/s | mean pair ratio | paired range | ratio of means |
|---|---:|---:|---:|---:|---:|
| Workstation | 2,705,385 | 2,502,325 | 0.9250 | 0.9190-0.9353 | 0.9249 |
| Server | 2,678,289 | 2,526,395 | 0.9436 | 0.9097-0.9757 | 0.9433 |

Every run reported zero collections and the deterministic completion marker.
The primary statistic is the mean of the five family/stock pair ratios; the
ratio of aggregated means is named separately. All 20 invocation rows include
pair, order, seed, operations, collection counts, observed Server/concurrent
GC and collector confirmation, binary identity, machine identity, and the
completion marker in `P1.3/raw/bulk-throughput-invocations.csv`. Claim-bit,
ReadyToRun, and tiering columns are explicitly `Requested*` launcher settings
and are labeled as not independently confirmed by the worker. The 5.6-7.5%
difference remains below the previously demonstrated 8.35% host resolution
floor and is reported as unresolved, not as a proven regression.

Stock disassembly for representative scalar, fill, and struct methods is
byte-identical between preserved P1.2 main and the changed CardTable runtime.
The new family calls are absent when the capability is unused.

## Limitations

- The runtime capability does not implement RC or an epoch policy. Those
  remain collector responsibilities.
- NativeAOT remains CardTable-only.
- Non-x64 targets are cross-built or source-audited, not claimed as family
  execution.
- Paper numbers are context, not .NET thresholds. The paper is the arXiv
  Extended Version, arXiv:2210.17175 (1 Nov 2022); its 1.6% field-barrier
  geomean is against no-barrier Immix and lies inside roughly +/-3% noise.
